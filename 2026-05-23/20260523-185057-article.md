微软在 2025 年 5 月把一套名为 dotnet/skills 的仓库推上了 GitHub Trending。这不是什么新框架或运行时，而是一组专门给 AI 编程助手用的“技能包”——你可以把它理解成，让 GitHub Copilot、Claude Code 或 Cursor 这类工具在写 .NET 代码时别瞎编的一套专业提示词和规则集。

仓库里拆出了 12 个独立插件，每个盯一个细分领域。dotnet 插件管基础编码任务，dotnet-data 处理 EF Core 数据访问，dotnet-msbuild 专门诊断构建失败和性能问题，dotnet-upgrade 负责跨版本迁移，dotnet-aspnet 覆盖中间件和 API 模式。有意思的是 dotnet11 这个插件，直接对还没正式发布的 .NET 11 新 API 做适配——微软显然不想让 AI 助手在版本更新时掉链子。每个插件都遵循 agentskills.io 这个开放标准，所以你拿去 OpenAI Codex 里也能用。

![dotnet/skills — Repository for skills to assist AI coding agents with .NET and C](20260523-185057-article-content-1.png)

安装方式暴露了微软的渠道策略。Copilot CLI 和 Claude Code 用户敲一行 `/plugin marketplace add dotnet/skills` 就能挂载整个市场，然后按需装具体插件。VS Code 这边要手动改 settings.json，把 `chat.plugins.marketplaces` 指向仓库地址——但官方特意标了“预览功能”，暗示这还不是最终形态。Cursor 的集成最干脆，直接把这个仓库注册成了内置市场，用户在 marketplace 面板搜 .NET 就能装。Codex CLI 用户则得用 `skill-installer` 工具逐个拉取 GitHub 上的技能目录。四种方式，覆盖了目前主流的 AI 编程入口。

还有个 Dashboard 页面挂在 dotnet.github.io/skills，实时跟踪每个插件的准确率和效率评分。这做法很微软——不跟你讲“我们觉得效果不错”，而是把指标公开晒出来。仓库的 CONTRIBUTING.md 也写明了怎么贡献新插件，说明他们打算把这个做成社区共建的项目，而不是内部闭门维护的工具集。

这仓库本质上在解决一个问题：AI 编程助手对 .NET 生态的认知太浅了。通用模型写 Python 可能还行，碰到 MSBuild 的 xml 配置、NuGet 的包版本冲突、或者 MAUI 的平台差异，输出经常是灾难。dotnet/skills 等于把 .NET 团队的知识蒸馏成机器可读的指令，塞进 AI 的上下文窗口。方向是对的，但真正效果取决于这些技能更新能不能跟上 .NET 半年一版的发布节奏——如果插件滞后三个月，开发者还不如自己翻文档。
